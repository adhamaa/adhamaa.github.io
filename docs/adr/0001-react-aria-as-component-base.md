# React Aria as the shadcn component base

This repo's `src/components/ui/` was generated by shadcn/ui on Radix UI. We are moving it to React Aria Components (`react-aria-components`, published by Adobe) via `shadcn init --base aria`, because the components that survive are the keyboard-driven ones — a command palette and a sortable table — and those are exactly where React Aria's focus management and screen-reader semantics earn their cost over Radix's.

## A note on the word "base"

"Base" means three different things in this area and they are easy to confuse:

- **`--base`** — the shadcn CLI flag selecting a headless primitive library. Accepts `base`, `radix`, `aria`.
- **Base UI** — the library that the value `base` refers to. It is shadcn's current default. We are not using it.
- **`baseColor`** — an unrelated `components.json` field describing the palette's neutral ramp.

When this repo says "the base", it means the primitive library: React Aria.

## Considered options

- **Stay on Radix.** Fully supported, zero work. Rejected: no accessibility gain, and the components needing it most are the ones we keep.
- **Base UI**, the current shadcn default. Rejected: switching defaults for its own sake, with no accessibility argument behind it.

## Consequences

- **`menubar` and `navigation-menu` have no React Aria implementation** in the shadcn registry (their `/docs/components/aria/` pages 404). Neither is used here — both were deleted as dead code — but anything needing them later must be hand-written or kept on Radix.
- **`cmdk` is dropped.** React Aria's answer to the command palette is `Autocomplete`, so `command.tsx` is a rewrite rather than a regeneration.
- **`sonner` stays.** It is React Aria's official toast answer as well as Radix's; the registry's `toast` component is Base-UI-only.
- Focus rings, hover affordances and keyboard behaviour change by design. Visual parity was explicitly *not* required for this migration.
